# From Operator to Reviewer

When every step of a process depends on you starting it, carrying it forward, and checking it at the end, you are the process. AI can change that, but only if you redesign the job rather than simply asking the model to do more.

The shift is from operator to reviewer. An operator performs each routine action. A reviewer decides what work matters, sets the standards, examines the result, and intervenes when [[ai-that-doesnt-wait|work that starts on its own]] reaches a boundary.

That is not a smaller job. It is a different one. You need enough visibility to know what the agent did, enough context to judge the result, and an easy way to correct the instructions when the same problem recurs. Without those pieces, “autonomy” simply hides work until it becomes a surprise.

For a student project, practice this shift on one narrow workflow. Define the trigger. Define the output. Define [[dont-grade-your-own-homework|an acceptance check independent from the first draft]]. Then let the agent prepare the first version while you review it. If you find yourself rewriting the same kind of error twice, the fix belongs in the skill or the knowledge base, not only in your next prompt.
